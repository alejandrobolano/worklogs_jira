# Building and Creating the Worklogs Jira Windows Installer

This guide describes how to build **Worklogs Jira** for Windows with Flutter and then package the generated application into a distributable `.exe` installer using **Inno Setup**.

> User names, local paths, URLs, publisher information, versions, GUIDs, and other environment-specific values are represented by placeholders and must be adapted to your environment.

## 1. Requirements

Before starting, make sure your Windows development environment includes:

- Flutter SDK installed and available from the terminal.
- Flutter Windows desktop support properly configured.
- The Windows development tools required by Flutter.
- Inno Setup installed to create the final installer.
- A local copy of the project source code.

Check the development environment first:

```powershell
flutter doctor
```

Then download the project dependencies:

```powershell
flutter pub get
```

## 2. Build the Windows Application

From the project root directory, run:

```powershell
flutter build windows
```

Flutter will build the application in release mode. For a Windows x64 build, the generated artifacts are normally located at:

```text
build/windows/x64/runner/Release/
```

This directory contains the application executable, for example:

```text
worklogs_jira.exe
```

### Important: Do Not Distribute Only `worklogs_jira.exe`

The `.exe` generated by Flutter should not be treated as a standalone executable. The `Release` directory also contains DLLs, resources, and other files required by the application at runtime.

Therefore, if you want to distribute the application without an installer, distribute the **entire contents of the `Release` directory** while preserving its directory structure.

For a more convenient distribution method, the next step packages these files into a Windows installer using Inno Setup.

## 3. Create an Installer with Inno Setup

Create an Inno Setup script, for example:

```text
WorklogsJiraInstaller.iss
```

A possible installer directory structure is:

```text
installer/
├── WorklogsJiraInstaller.iss
├── assets/
│   └── app_icon.ico
└── output/
```

This structure is only an example. The paths in the `.iss` file can be changed to match your project layout.

## 4. Example `.iss` Script

The following example replaces personal and machine-specific information with placeholders. Update the `<...>` values before compiling the installer.

```iss
; Worklogs Jira - Inno Setup
; Replace the <...> values with those for your project/environment.

#define MyAppName "Worklogs Jira"
#define MyAppVersion "<APP_VERSION>"
#define MyAppPublisher "<PUBLISHER>"
#define MyAppURL "<PROJECT_OR_PRODUCT_URL>"
#define MyAppExeName "worklogs_jira.exe"

[Setup]
; Generate your own GUID from Tools > Generate GUID in Inno Setup.
; Do not reuse an AppId belonging to another application.
AppId={{<YOUR-APPLICATION-GUID>}
AppName={#MyAppName}
AppVersion={#MyAppVersion}
AppMutex=WorklogsJiraAppMutex

AppPublisher={#MyAppPublisher}
AppPublisherURL={#MyAppURL}
AppSupportURL={#MyAppURL}
AppUpdatesURL={#MyAppURL}

; Install for the current user without requiring administrator privileges.
DefaultDirName={localappdata}\Programs\{#MyAppName}
DisableDirPage=no
DirExistsWarning=no
PrivilegesRequired=lowest

CloseApplications=yes
RestartApplications=no

; Example paths. Adapt them to your environment.
OutputDir=<INSTALLER_OUTPUT_DIRECTORY>
OutputBaseFilename=WorklogsJiraSetup-{#MyAppVersion}
SetupIconFile=<PATH_TO_APP_ICON>\app_icon.ico

Compression=lzma2/ultra64
SolidCompression=yes
LZMAUseSeparateProcess=yes
LZMADictionarySize=65536
WizardStyle=modern

CreateUninstallRegKey=yes
UpdateUninstallLogAppName=yes

[Languages]
Name: "english"; MessagesFile: "compiler:Default.isl"
Name: "spanish"; MessagesFile: "compiler:Languages\Spanish.isl"

[Tasks]
Name: "desktopicon"; Description: "{cm:CreateDesktopIcon}"; GroupDescription: "{cm:AdditionalIcons}"; Flags: unchecked

[Files]
; Point to the COMPLETE Flutter Release output, not only the .exe file.
Source: "<PROJECT_PATH>\build\windows\x64\runner\Release\*"; DestDir: "{app}"; Flags: ignoreversion recursesubdirs createallsubdirs

[Icons]
Name: "{autoprograms}\{#MyAppName}"; Filename: "{app}\{#MyAppExeName}"
Name: "{autodesktop}\{#MyAppName}"; Filename: "{app}\{#MyAppExeName}"; Tasks: desktopicon

[Run]
Filename: "{app}\{#MyAppExeName}"; Description: "{cm:LaunchProgram,{#StringChange(MyAppName, '&', '&&')}}"; Flags: nowait postinstall skipifsilent
```

### Values to Replace

- `<APP_VERSION>`: application version displayed by the installer.
- `<PUBLISHER>`: developer, company, or organization name.
- `<PROJECT_OR_PRODUCT_URL>`: project, product, or support website.
- `<YOUR-APPLICATION-GUID>`: unique identifier for this application.
- `<INSTALLER_OUTPUT_DIRECTORY>`: directory where Inno Setup will save the generated installer.
- `<PATH_TO_APP_ICON>`: directory containing `app_icon.ico`.
- `<PROJECT_PATH>`: path to the root of the Flutter project.

> **Important about `AppId`:** once the application has been released, keep the same `AppId` for future versions of the same application. Generate a new one only for a different application.

## 5. Compile the Installer

1. Open **Inno Setup Compiler**.
2. Open `WorklogsJiraInstaller.iss`.
3. Verify the paths and application version.
4. Select **Build > Compile**, or use the **Compile** action in the IDE.
5. If compilation succeeds, the installer will be created in the directory configured with `OutputDir`.

The generated filename will look similar to:

```text
WorklogsJiraSetup-<APP_VERSION>.exe
```

This is the installer that can be distributed to Windows users.

## 6. What the Installer Does

The example script:

- Copies all files generated by the Flutter Windows build into the installation directory.
- Installs the application for the current Windows user.
- Does not request administrator privileges because `PrivilegesRequired=lowest` is used.
- Creates an application shortcut in the Programs menu.
- Optionally allows the user to create a desktop shortcut.
- Registers the application so it can be uninstalled normally.
- Offers to launch Worklogs Jira after installation.
- Includes the application version in the generated installer filename.

## 7. Complete Release Flow

The basic release process can be summarized as follows:

```text
Flutter source code
       │
       ▼
flutter pub get
       │
       ▼
flutter build windows
       │
       ▼
build/windows/x64/runner/Release/
       │
       ▼
Inno Setup + WorklogsJiraInstaller.iss
       │
       ▼
WorklogsJiraSetup-<VERSION>.exe
       │
       ▼
Installer testing
       │
       ▼
Distribution / publishing
```

Before publishing a new version, it is recommended to test both a clean installation and an upgrade from a previous version.

## 8. Code Signing (Optional)

The installer can be digitally signed using a code-signing certificate. This should be considered a separate step from generating the installer and requires a valid certificate and the appropriate signing tool configuration.

Do not store passwords, private certificates (`.pfx`), or other secrets in the repository. If the process is automated with CI/CD, store sensitive values using the secret-management system provided by the CI/CD platform.

## 9. Release Checklist

Before distributing a new version:

- [ ] Update the application version.
- [ ] Run `flutter pub get`.
- [ ] Run `flutter doctor` if there are build environment issues.
- [ ] Run `flutter build windows`.
- [ ] Verify that the application works correctly from the `Release` directory.
- [ ] Update `MyAppVersion` in the `.iss` file.
- [ ] Verify the installer paths, icon, and `AppId`.
- [ ] Compile the `.iss` script with Inno Setup.
- [ ] Install the generated package in a test environment.
- [ ] Verify shortcuts, application startup, and uninstallation.
- [ ] Sign the installer if a code-signing certificate is available.
- [ ] Publish the installer.
